# Problem statement 26117

**Smart India Hackathon 2026** · Software · Theme: Smart Automation
**Organisation:** Mangalore Refinery and Petrochemicals Limited (MRPL)

## Title

Sovereign On-Premise Agentic AI Workbench using Open-Weight Multimodal LLMs for
Confidential Industrial Work

## Background (paraphrased)

Refineries, PSUs, defence-linked manufacturing and government offices produce a
great deal of routine but sensitive knowledge work: approval notes, board
presentations, engineering calculations, internal tools, review of scanned
drawings and inspection reports. None of it can go to cloud assistants, because
the underlying data — P&IDs, financials, vendor negotiations, unreleased
designs, internal correspondence — must stay on premises. So people either do
the work by hand, or quietly paste confidential material into public tools
anyway. Open-weight reasoning models are now good enough to build a genuinely
useful assistant on, but nothing deployable exists.

## What it asks for

A self-hosted, air-gapped workbench on the organisation's own GPU server, where
nothing leaves the premises:

- **Not locked to one model.** Several open-weight models at once, with the
  right one picked automatically per task. New models addable later without
  redesign.
- **Genuinely agentic.** Plans multi-step work, calls local tools — file read
  and write, sandboxed code execution, spreadsheet work, internal document
  search — and iterates rather than answering once.
- **Multimodal.** Scanned PDFs, handwritten notes, engineering drawings,
  photographs, through on-device OCR and vision models.
- **Real deliverables.** Approval notes, PPT / Word / Excel files, working code,
  calculations with steps shown — not just chat replies.
- **Grounded** in the organisation's manuals, SOPs and past correspondence
  through a local knowledge base.

## Dataset guidance

> Open-source models and publicly available document samples (sample scanned
> PDFs, sample P&IDs from open datasets) to be used for demonstration; no
> proprietary data required.

Our fixtures are **synthetic, generated by scripts**, so every one has an exact
ground truth:

- `scripts/make_scanned_sample.py` — an inspection report rendered to images and
  rebuilt as a PDF with no text layer
- `scripts/make_pid_sample.py` — an ISA-5.1 P&ID with nine known tags and three
  line numbers
- `data/kb/*.md` — MRPL-style SOP, inspection procedure and equipment register,
  written for the demo

Drawn rather than downloaded so that "did the model read it correctly" has an
answer instead of a judgement call.

### Suggested six-slide outline

1. **Title** — PS 26117, team name, problem statement title.
2. **The idea** — the gap: confidential work done by hand or pasted into public
   tools. One architecture diagram (use the topology in
   `docs/ARCHITECTURE.md`).
3. **Technical approach** — tiered registry and deterministic router; agent loop
   with nine local tools; hybrid RAG with enforced citations; vision for scans
   and drawings; containment by an unroutable network. Name the models.
4. **Feasibility** — measured, not claimed: flagship question 6s; scanned page
   48s cold, 0s cached; drawing 12s; 117 automated tests; tripwire blocked in
   1ms. Hosted today, one configuration change to local — say so plainly.
5. **Impact** — MRPL-specific: approval notes, inspection review, P&ID lookup;
   zero egress by construction; every action attributed in an audit log.
6. **References** — repository, unlisted video link, model cards, the
   benchmark in `docs/model-benchmark.md`.

**Put the limitations on slide 4 rather than let a judge find them.** The
project's strongest asset is that its claims are true; the list is in
`docs/ROADMAP.md` under "Known limitations".
